# Contract: Deploy Definitions

This contract fixes the shape of the two version-controlled deploy definitions this feature
adds. The unit specifications assert **exactly these properties**, structurally, on the parsed
files — so a definition that drifts from this contract fails a mandatory check rather than
being discovered at deploy time. See [research.md R-009](research.md) for why the assertions
are structural rather than substring searches, and [R-001](research.md) and [R-003](research.md)
for why each file lives where it does.

Both definitions carry **variable names and non-secret settings only** (FR-028). Neither
contains a secret value, a placeholder that looks like one, or a connection string.

---

## 1. `render.yaml` — Render Blueprint

**Location**: repository root. **Reason**: a Blueprint defaults to `render.yaml` at the
repository root; elsewhere it must be registered by path.

**Shape the tests assert:**

| Property | Required value | Requirement |
|---|---|---|
| exactly one service, of type `web` | one entry under `services` | FR-013 |
| runtime | `node` | The deployed artefact is the foundation's verified build, produced by the repository's own commands rather than a second build |
| build command | the repository's own build command, run from the repository root | FR-013 |
| start command | `npm run db:migrate && npm run start --workspace @nexuserp/api` | FR-015 — migrations run here, before the service listens |
| plan | `free` | The specification's chosen entry plan; its limits are documented, not engineered around |
| health path | `/api/v1/health` | FR-023 — and the test also asserts this **equals the route the service actually serves** |
| deploy trigger | `checksPass` | FR-010 |
| every `envVars` entry | has a `key`, and exactly one of `value`, `sync: false`, `generateValue: true` | FR-028 |
| secret-bearing entries | `sync: false` or `generateValue: true`, and **no** `value` | FR-027, FR-028 |
| `SESSION_SECRET`, `CSRF_SECRET` | `generateValue: true` | Platform-generates a 256-bit value; never transmitted to a human |
| the database connection variable | `sync: false` | It embeds a credential and cannot be generated |
| `PORT` | **not declared** | FR-034 — the platform provides it; declaring it would override the platform's port |
| any value matching a secret pattern | none | FR-028, SC-006 |
| `preDeployCommand` | **absent** | FR-015 — migrations run in the start command; a second migration route is forbidden |

**Intended content** (variable values are non-secret and account-specific; the runbook names
the substitutions a reader makes):

```yaml
# Render Blueprint for the NexusERP staging service.
#
# The deployable artefact is the repository's own build, produced by the commands below,
# so no second build exists to drift from the verified one.
#
# PORT is deliberately NOT declared: Render provides it, and naming it here would override
# the platform's value with a fixed one.
#
# No secret value appears in this file. DATABASE_URL is entered once in the Render
# Dashboard (sync: false); the two application secrets are generated by Render
# (generateValue: true).
#
# No preDeployCommand: the free plan provides none, so the start command applies migrations
# before serving, and a second migration route is forbidden.

services:
  - type: web
    name: nexuserp-api-staging
    runtime: node
    plan: free
    buildCommand: npm ci && npm run build --workspace @nexuserp/shared && npm run build --workspace @nexuserp/api
    startCommand: npm run db:migrate && npm run start --workspace @nexuserp/api
    healthCheckPath: /api/v1/health
    autoDeployTrigger: checksPass
    envVars:
      - key: NODE_ENV
        value: production
      - key: LOG_LEVEL
        value: info
      - key: CORS_ORIGINS
        value: https://nexuserp-staging.vercel.app
      - key: TRUST_PROXY
        value: "1"
      - key: DATABASE_URL
        sync: false
      - key: SESSION_SECRET
        generateValue: true
      - key: CSRF_SECRET
        generateValue: true
```

`CORS_ORIGINS` is the frontend's own origin and is an explicit allowlist, never a wildcard: the
environment schema rejects `*` because a wildcard origin with credentials lets any site issue
authenticated requests as the user. With the rewrite in place the browser's API calls are
same-origin and CORS is not exercised, but the variable remains required and non-wildcard.

## 2. `vercel.json` — Vercel project configuration

**Location**: `frontend/vercel.json` — **inside** the Root Directory. **Reason**: Vercel
honours a configuration file only when it sits in the project's Root Directory; the same file
at the repository root is ignored.

**Project settings that live outside the repository** (documented in the runbook, because they
cannot be expressed in this file):

| Setting | Value | Requirement |
|---|---|---|
| Root Directory | the frontend workspace | Decides *what* is built |
| Include source files outside of the Root Directory in the Build Step | enabled | The frontend depends on the `shared` workspace, which is outside the Root Directory |

**Shape the tests assert:**

| Property | Required value | Requirement |
|---|---|---|
| the file parses as JSON | — | — |
| `rewrites` is a non-empty ordered array | — | FR-006 |
| the **first** rewrite's source matches the `/api` path segment | `/api/:path*` | FR-005, FR-006 |
| the first rewrite's destination preserves the path | an absolute service URL ending in the same `/api/…` path | FR-006 |
| the **second** rewrite is the single-page fallback | source `/(.*)`, destination `/index.html` | SPA routing |
| the API rewrite's index | strictly less than the fallback's index | The specification's edge case: an API request must reach the service, a page route must reach the interface |
| the API rule matches the `/api` **segment**, not a string prefix | no glob such as `api*` | A page route whose text merely begins with `api` must not be forwarded |
| `installCommand` installs from the repository root with the committed lockfile | changes up out of the Root Directory, then `npm ci --frozen-lockfile` | FR-049's rule: the deployed tree is the committed tree |
| `buildCommand` builds the `shared` workspace **before** the frontend workspace | `@nexuserp/shared` precedes `@nexuserp/web` | The frontend imports the shared package's compiled output |
| `outputDirectory` | `dist`, resolved against the Root Directory | The frontend's own build output |
| `framework` | `vite` | Removes framework mis-detection on a repository whose root is not the application |
| any value matching a secret pattern | none | FR-028, SC-006 |

**Intended content**:

```json
{
  "$schema": "https://openapi.vercel.sh/vercel.json",
  "framework": "vite",
  "installCommand": "cd .. && npm ci --frozen-lockfile",
  "buildCommand": "cd .. && npm run build --workspace @nexuserp/shared && npm run build --workspace @nexuserp/web",
  "outputDirectory": "dist",
  "rewrites": [
    {
      "source": "/api/:path*",
      "destination": "https://nexuserp-api-staging.onrender.com/api/:path*"
    },
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

**Why the order is the contract.** Rewrites are evaluated in order and the **first match wins**.
Putting the API rule first is what makes a health request at the staging address reach the
service; putting the fallback second is what makes every other path reach the interface. The
fallback never matches an API path, because the API rule has already claimed it. Reversing the
two makes the interface answer every request with `index.html` — the page loads, the health
panel fails, and nothing in the deployment says why.

**Why the API rule matches a segment.** `/api/:path*` requires the literal first path segment
`api`. A single-page route such as `/apiary` or `/api-docs` is a *different* first segment, so
it falls through to the fallback and reaches the interface. A string-prefix rule would forward
it to the service, which is the collision the specification's edge case rules out.

**Where the service hostname lives.** In this file, and nowhere in application code. FR-005
requires the interface to call the API through relative paths under `/api` and forbids it from
holding the service's hostname in its configuration; the rewrite target is where the hostname
belongs, and it is version-controlled here so it is reviewable. The value is account-specific
and is not a secret; the runbook names it as a substitution a reader makes after creating the
service.

## 3. What neither definition may contain

| Never present | Because |
|---|---|
| a secret value, a connection string with a credential, or a high-entropy token | FR-027, FR-028, SC-006 |
| a wildcard cross-origin rule | The environment schema rejects `*`; a wildcard with credentials lets any site act as the user |
| a fixed `PORT` on the service | FR-034 — the platform's port must reach the service unmodified |
| both a pre-deploy migration command and a migration step in the start command | FR-015 — the schema must have one route, not two |
